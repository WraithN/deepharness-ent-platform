# Markdown 编辑器工具栏：格式开关与块级换行缺陷

## 现象

产品空间文档编辑器（`MarkdownEditor.tsx`）富文本工具栏存在两个交互缺陷：

1. **格式不可取消**：对已加粗的文本再次点击「B」，会再包一层 `****` 而非取消加粗；对一级标题行点击「H2」，得到 `# ## test2`（前缀叠加）而非切换为二级标题。
2. **块级元素不换行**：在行内文本中间插入代码块或表格时，片段直接拼接在当前行（如 `abc```…`、文字后紧跟 `| 列1 |`），导致 Markdown 渲染错误。

## 根因

工具栏动作执行函数 `applyAction` 只有「单向插入」逻辑：

- `wrap` 类动作（加粗/斜体/代码等）无条件在选区两侧追加包装符，未检测选区是否已被相同符号包裹。
- `linePrefix` 类动作（标题/列表/引用）无条件在行首插入前缀，未剥离行首已有的同类前缀，因此无法切换级别或取消。
- `insert`（表格/分割线）与代码块 `wrap` 未保证片段前后换行，块级语法必须独立成行才能被正确解析。

## 解决方案

在 `applyAction` 中增加三类处理：

1. **wrap 开关**：插入前检测 `value` 中选区两侧是否已是相同的 `before`/`after`，若是则移除包装符（再次点击即取消格式）。
2. **行级前缀替换/开关**：为 `ToolbarAction` 增加 `lineMatch` 正则（标题 `/^#{1,6}\s+/`、列表 `/^(?:[-*+]\s+|\d+\.\s+)/`、引用 `/^>\s+/`），应用前先剥离行首同类旧前缀；旧前缀与目标完全相同则为取消（toggle off），否则写入新前缀（支持 H1↔H2 切换）。
3. **块级换行**：`insert` 片段与 `block: true` 的代码块 wrap 在插入时检测前后字符，非行首自动补 `\n`，保证独立成行。

## 验证结果

- `tsc --noEmit -p tsconfig.check.json`：0 错误
- `pnpm build`：6/6 成功
- 逻辑走查：`# test2` 选中后点 H2 → `## test2`（不再叠加）；再点 H2 → `test2`（取消）；`**加粗**` 选中后点 B → `加粗`（取消）；行内插入代码块/表格自动换行独立成行
