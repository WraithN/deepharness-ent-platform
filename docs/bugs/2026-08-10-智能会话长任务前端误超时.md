# 2026-08-10-智能会话长任务前端误超时

## 现象

`/code` 等指令执行时间较长时，前端在约 10 分钟后提示：

> 模型响应超时，未收到任何输出。请检查网络、模型配置或账户余额后重试。

用户观察到 agent 实际上一直在调用工具（bash/edit 等），并没有停止响应。

## 根因

全链路排查后确认是**前端 10 分钟无事件看门狗误判**：

1. 后端 `AGUIHandler.AgentRun` 在工具执行期间会持续向前端发送 SSE 心跳 `: heartbeat\n\n`（`apps/dh-backend/gateway/handler/agui_run.go:968`），保证连接存活。
2. 前端 `use-ag-ui-chat.ts` 的 `lastEventAt` 只在解析到 **data 事件** 时更新（`use-ag-ui-chat.ts:1569`）。
3. SSE 注释块 `: heartbeat` 会被 `parseSSE` 丢弃，不计入 `lastEventAt`。
4. 因此只要某个长工具执行超过 10 分钟且期间没有新的 AG-UI data 事件，前端 `noEventTimer` 就会 `abortController.abort()`，展示“模型响应超时”。

次级问题：后端 `context.Background()` 调用 gatewayd，前端 abort 后后端仍继续运行，但前端已清理 active run，导致用户看不到最终结果和 `[[PROJECT:...]]` 卡片。

## 解决方案

在 `apps/dh-frontend/src/hooks/use-ag-ui-chat.ts` 的 SSE 读取循环中：

- 只要 `reader.read()` 返回非空 chunk，就立即更新 `lastEventAt`，不再只依赖 `parseSSE` 出的 data 事件。
- 这样后端每 15s 发送的心跳注释也能被识别为“连接活跃”，长工具执行期间不会再误触发 10 分钟超时。

```ts
const { done, value } = await reader.read();
if (done) break;
if (value && value.byteLength > 0) {
  lastEventAt = Date.now();
}
```

验证：`pnpm --filter @repo/dh-frontend check-types` 通过；重启后 dev 环境正常。

## 影响范围

- `/code`、`/debug`、`/refactor` 等可能触发长工具链的指令。
- 之前 `/code` 指令看似“没有给出卡片”，实际是因为前端在 comet-open 阶段就超时中断，agent 后续输出的 `[[PROJECT:...]]` 标记未被前端接收。
