# /code 模板工程目录解析歧义问题

## 现象

当用户通过 `/code` 模板发起类似“开发一个登录的 html 页面”的请求时，即使 prompt 中已标注：

> 当前关联代码库: test

模型仍可能将代码写入 `projects/login-page/`，而不是关联代码库 `test` 对应的工程目录。导致：

1. 用户期望的修改没有落到指定工程里。
2. 在 `projects/` 下产生大量以“任务描述”命名的孤立目录。
3. 多工程场景下，模型无法判断该修改哪一个工程。

## 根因

`/code` 模板中的工程目录指引存在歧义：

> 创建工程代码时，必须将文件写入当前工作目录下的 `projects/{项目名}/` 子目录中。

该规则把“关联代码库”降格为“参考”，把 `projects/{项目名}/` 作为唯一合法落点。结果：

- 当 `projects/` 目录为空时，模型只能自己构造一个项目名（如 `login-page`），而不是写入关联代码库。
- 当 `projects/` 下存在多个工程时，“对应的工程”没有明确指代对象。
- 关联代码库与 `projects/` 目录之间的映射关系未在 prompt 中说明。

## 解决方案

### 1. 系统级 prompt 模板修复（推荐）

将 `/code` 模板的工程目录规则改为：

```text
当前关联代码库: {codeLibraryName}，目标路径: {codeLibraryPath}。

工程目录选择优先级：
1. 若 prompt 指定了【关联代码库：xxx】，则优先在关联代码库对应目录创建/修改文件。
   - 若该目录尚未 clone 到 projects/ 下，先执行 git clone。
   - 若当前工作目录本身就是该代码库，则直接在当前目录操作。
2. 若用户明确要求创建新的独立工程并给出项目名，才允许创建 projects/{项目名}/。
3. 若 projects/ 下存在多个工程且目标不明确，必须询问用户要修改哪一个。
```

### 2. 项目级兜底规则

在 `AGENTS.md` 中新增**规则13：工程目录选择优先级**，作为项目级兜底约束：

- 关联代码库优先。
- 已有工程优先。
- 多工程必须确认。
- 新建工程需显式项目名。

## 验证结果

- `AGENTS.md` 已追加规则13，明确工程目录选择优先级。
- 规则10 已同步更新为“规则1-9，规则11-13”，确保新规则持久化。

## 后续行动

建议同步修改 `/code` 系统模板，将【关联代码库】提升为默认目标工程，而不是仅作为“参考”。
