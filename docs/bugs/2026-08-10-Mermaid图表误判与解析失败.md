# 2026-08-10-Mermaid图表误判与解析失败

## 现象

聊天 Markdown 渲染出现两类 Mermaid 异常：

1. 真正的 `graph TD` 图被 Mermaid 解析失败，展示红色“图表渲染失败”错误块，原文直接裸露在页面里。
2. 纯注释/说明性代码块（如 `// 收集用户输入：...`）被误判为 Mermaid，渲染出“No diagram type detected...”错误。

## 根因

1. `MermaidBlock` 解析失败时直接展示原始代码文本，体验差，且会把 Markdown 正文打散。
2. Mermaid 检测逻辑虽然通过 `isMermaidDiagramCode` 过滤了注释行，但仍有边缘场景（如 AI 错误地把非 Mermaid 内容标记为 `mermaid` 语言）会把非图表代码送进 `MermaidBlock`，导致“No diagram type detected”。

## 解决方案

在 `apps/dh-frontend/src/components/chat/MermaidBlock.tsx` 中：

- 解析失败时不再裸奔展示原文，而是回退为带语法高亮的代码块（`SyntaxHighlighter`），保留“图表渲染失败，已回退为代码块”的提示。
- 这样即使检测/语法出现问题，页面也能以代码块形式正常展示，不再出现大片红色错误块。

同时保留 `apps/dh-frontend/src/lib/mermaid-utils.ts` 作为 Mermaid 检测的统一事实来源，
`MarkdownView.tsx` 和 `ChatCodeBlock.tsx` 均复用该函数，避免多处启发式规则不一致。

验证：`pnpm --filter @repo/dh-frontend check-types` 通过。
