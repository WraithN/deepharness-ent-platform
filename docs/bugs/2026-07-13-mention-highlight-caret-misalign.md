# @提及 高亮后光标错位（看起来落在字中间）

## 现象

Chat 输入框引用文档后，在 `@文档名` 提及块之后继续输入文字，光标显示位置超前于实际文字，看起来落在某个字的中间，且越往后偏差越大。

## 根因

高亮叠层方案中，textarea 文字透明、光标由 textarea 自身文本布局绘制，而可见文字由叠层 div 渲染。高亮 span 使用了 `px-1`（左右各 4px 内边距），使叠层中提及块后的文字整体向右偏移 8px，但 textarea 的光标位置不含这段 padding——两套布局的文本步进宽度不一致，导致提及块之后光标与文字错位，偏差随距离累积。

## 解决方案

将高亮 span 的 `px-1` 改为 `px-0.5 -mx-0.5` 组合：负外边距与等值内边距相互抵消，背景/阴影仍向两侧各延伸 2px 获得视觉留白，但文本步进宽度与 textarea 完全一致。已在代码注释中标注此约束，避免后续修改高亮样式时重新引入错位。

验证结果：canvas `measureText` 按相同字体计算的光标 X 与叠层实际渲染文本右边界相差 0.02px（亚像素级），截图确认提及块后文字与光标对齐；`tsc` 0 错误、`pnpm build` 通过。
