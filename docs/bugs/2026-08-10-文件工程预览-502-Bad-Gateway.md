# 2026-08-10-文件工程预览-502-Bad-Gateway

## 现象

在「智能会话」和「个人工作台」中，文件/工程预览请求大量返回 `502 Bad Gateway`：

- `GET /api/v1/files/content?path=...`
- `GET /api/v1/projects/check?path=...`

浏览器控制台显示这些请求由 `ProjectCard.tsx`、`FileAttachmentCard.tsx` 等组件发起，
`dh-backend` 日志中对应 `http: proxy error: dial tcp 127.0.0.1:8090/8100: connect: connection refused`。

## 根因

`direct-host` 模式下，`dh-backend` 的 `Manager.startProcessesLocked` 启动 per-user `personal-stub` 子进程后，
**没有等待其 HTTP 监听就绪** 就把容器信息返回给上游中间件。后续请求立即被 `StubProxy` 反向代理到该端口，
但此时 `personal-stub` 还在部署 skills、启动 gatewayd，HTTP 服务尚未 bind，导致连接拒绝和 502。

日志中可见时间差：`[DirectHost] personal-stub started ...` 与 `Personal Stub starting on port ...` 相差约 30s；
期间已有文件请求打到未就绪的端口。

## 解决方案

在 `apps/dh-backend/agent/provisioner/directhost/manager.go` 中：

1. 启动 `personal-stub` 进程后，调用 `waitForStubReady` 轮询 `http://{host}:{port}/health`。
2. 超时（45s）则 kill 进程并返回错误，避免把未就绪的端口暴露给代理层。
3. 在 `Acquire`/`Provision` 中持有 `m.mu` 等待就绪，保证同用户后续请求在锁释放后拿到的 stub 已经是可用的，
   消除并发请求的竞态。

修复后重启验证：

- `testuser2` 首次请求文件内容时，backend 等待 `personal-stub` 就绪，最终返回 `404`（文件不存在）而非 `502`。
- `developer` 的文件/工程预览请求均返回 `200`。
- `/tmp/dh-backend.log` 不再出现对应端口的 502 代理错误。
