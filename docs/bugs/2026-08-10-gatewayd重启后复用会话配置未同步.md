# 2026-08-10-gatewayd重启后复用会话配置未同步

## 现象

`/code` 等长任务指令在新建会话时正常，但在 **刷新页面/重进会话** 或 **gatewayd 重启后复用旧 thread** 时，
agent 长工具调用仍可能在约 120s 后被判定 stalled 并中断，导致 comet 流程夭折、最终没有 `[[PROJECT:...]]` 卡片。

## 根因

空间级 agent 配置（模型、watchdog_timeout 等）**只在 `CreateSession` 时同步到 gatewayd**（`session.go`）。
前端刷新/重进会复用已有 threadId，走 `AgentRun → AttachAgent`，此时不再同步配置；
gatewayd 重启后丢失内存中的配置，回退到默认 120s watchdog，长工具链被误杀。

## 解决方案

让配置同步发生在 **每次 agent run attach 完成后、chat 请求发送前**：

1. `apps/dh-backend/agent/client/agui_client.go`
   - `attachAgentWithKey` / `attachWithReuse` 返回 `instance_id`；
   - 新增 `attachedInstances` 缓存 threadId → instanceId；
   - 新增 `RunWithOnAttached`，在 attach 完成、chat 发送前触发 `onAttached` 回调；
   - 新增 `UpdateAgentConfig`（与 `GatewaydClient` 行为一致）。
2. `apps/dh-backend/gateway/handler/agui.go`
   - `AGUIHandler` 新增 `agentConfigSvc` 字段与 `SetAgentConfigService`。
3. `apps/dh-backend/gateway/handler/agui_run.go`
   - `executeAgentRun` 使用 `RunWithOnAttached`，在回调中读取空间配置并调用 `UpdateAgentConfig`；
   - 新增 `syncAgentConfigToGatewayd` 与 `resolveRunPluginKey`。
4. `apps/dh-backend/gateway/server/server.go`
   - 创建 `aguiHandler` 后调用 `SetAgentConfigService(defaultAgentConfigService)`。

这样无论新建会话还是复用会话，只要 run 发生 attach，gatewayd 都会拿到最新的
`watchdog_timeout_secs`（默认 600s），不会再回退到 120s。

## 附加修复：gatewayd 启动初期 workspace 未就绪

首次 run 发生在 personal-stub/gatewayd 刚启动时，`AttachAgent` 可能返回
`workspace_path not ready: waiting for platform to confirm a workspace path`。
原逻辑对未知错误直接放行到 chat，导致首次 `/code` 得到 `RUN_ERROR`。

已在 `attachWithReuse` 中对 `workspace_path not ready` 做有限重试（15 次 × 2s），
等待 gatewayd workspace readiness gate 就绪后再进入 chat，避免冷启动首跑失败。

## 验证

- `go vet ./apps/dh-backend/...` 通过。
- `go build` 通过，dev 环境已重启。
- 后续触发 `/code` 时，日志应出现 `synced agent config to gatewayd: threadId=... instanceId=... watchdog=600`。
